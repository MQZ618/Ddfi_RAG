## 3. 关键事实

### 3.1 附件生命周期

本轮证明了“同一会话、下一轮、不重新上传”可以继续使用已提供的附件引用。该结果不能推导出跨会话持久化；此前 E02 已观察到新一轮 `files=[]`、Agent 要求重新上传的情况。

### 3.2 任务路由与上下文成本

同一短句压缩在空白会话中显示 12,593 和 12,453 tokens；在包含三份附件摘要和前序输出的长会话中显示约 65,837 tokens。该差异是页面原始字段，不是独立成本模型，至少说明长会话上下文会显著抬高简单任务的页面 Token。

英文转换的页面思考过程明确包含：检查可用能力、加载匹配 Skill、读取 manifest 和核心片段、执行完整 polishing protocol。它与本地 Prompt/DSL 新增的最小过程和预算契约不一致；由于没有 Live App 配置绑定证据，本报告将其记为“当前 Live 行为”，不归因于本地代码已失效。

E17/E18 证明已有附件会话可以继续完成中文长段落写作与第二段定点闭环修改；E18 的非目标段落逐字保留，符合 closed-world 变换边界。两条证据不能替代“全新会话上传一次后连续三轮”的完整序列验收。

### 3.3 科研写作质量

- 中文材料摘要能够区分主题、目标、已完成工作和待验证事项，并能定位文件一/三的具体矛盾。
- 英文转换保持了“已有三类研究线索—尚无统一任务—单图像局限—需要定义状态并跨事件验证”的论证关系。
- 未观察到伪造实验数字或引用；材料自身的 Unknown、待核实和跨文献综合判断被保留为待验证边界。
- E16 的正式结果仍包含 `Revision notes`，而用户只要求正文和五个术语映射；这属于轻度输出格式漂移，也会增加用户可见的 Agent 腔。
