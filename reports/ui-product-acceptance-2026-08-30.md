# 智慧科研工作台 UI 产品化验收记录

日期：2026-08-30

## 验收范围

- 真实浏览器打开本地工作台并检查视觉布局；
- 左侧导航、快捷任务、新建会话、移动端菜单、材料上传、附件移除、发送任务；
- 单文件和三文件上传后的真实 Dify 对话链路；
- 轻量任务不启动复杂流程；明确要求不生成文件时不出现交付物；
- 控制台错误、前端自动测试和项目 Python 测试。

## 结果

- 左侧导航由无动作的高亮按钮改为 4 个真实页面内定位：研究总览、材料与文献、任务中心、证据审查；删除没有实现基础的“我的课题”。
- 5 个快捷任务均能把可编辑任务模板填入输入框。
- 新建研究会话能清空会话、附件、证据状态和交付物状态。
- 单个研究材料上传后页面显示真实附件；带附件发送后 Dify 返回真实回答。
- 三份测试材料可批量上传，页面显示 3 份材料；三文件联测完成并返回材料主题确认。
- 三文件任务明确要求“不生成文件”时未出现交付物面板。
- 移动端菜单可打开侧栏，点击导航后可定位并自动收起侧栏。
- 证据状态更新不再覆盖状态圆点；完成态使用绿色完成样式。
- 本轮浏览器控制台未发现 error/warn。

## 测试证据

- `web-client`: `npm test` → 16 passed。
- 项目 Python 测试：`pytest -q` → 57 passed。
- `node --check`: `server.mjs`、`public/app.mjs`、`public/navigation.mjs`、`public/markdown.mjs` 均通过。
- `git diff --check` 通过。

## 测试环境限制与绕行

浏览器自动化直接点击隐藏的 `input[type=file]` 会被控件拒绝；这不是用户可见上传入口的失败。改用页面可见的“添加材料” label 触发 file chooser 后，单文件、三文件上传和后续 Dify 对话均成功，因此本轮采用可见入口作为真实 Web E2E 路径。

本轮未修改 Dify Core、未重建镜像、未提交本地 `.env` 或任何 API 密钥。
