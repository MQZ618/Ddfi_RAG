## 4. 对目标问题的回答

1. **中文论文写作**：短段落结构和学术措辞基本可靠，能形成“现状—限制—研究问题”的推进；但会加入未经输入明确支持的应用背景句。
2. **英文论文写作**：E03 的英文段落自然、术语稳定，未出现明显中文直译腔；否定性判断被正确标为需核查。
3. **期刊层级调整**：能改变论证密度和应用直接性，但 Q3 风格不能以新增事实背景换取“应用感”。
4. **逻辑跳跃**：E06 能识别跨任务推断、全称断言、因果方向错误和证据强度不足。
5. **段落与章节结构**：E04/E05 显示段落中心和 IMRaD 职责较清楚；Discussion 能区分假设与结果。
6. **AI 味/Agent 腔**：正式输出总体克制；内部过程会暴露 `task profile`、Skill 路由和“按协议交付”等 Agent 腔，生产 UI 若展示思考过程会影响用户观感。
7. **高级期刊包装风险**：未出现“首次”“显著优于所有方法”等夸大词，但 Q3 版本的应用背景扩写说明仍需加强事实闭合检查。
8. **无数据证据边界**：E05 明确将 Results 写成“待填”，没有伪造数字或结果。
9. **简单任务路由**：E08 未启动可见复杂流程，符合轻量任务预期。
10. **Review-only**：E06 未越权改正文，达到要求。
11. **中英文转换**：E03 保持了原始论证关系和事实强度。
12. **重复稳定性**：E10 三次核心句完全一致；耗时有波动，但行为未漂移。

## 5. 回归缺陷与后续优先级

### P0：附件跨轮次不可用

文件可在首条消息中被 Agent 读取，但下一轮 `files=[]`，无法继续基于附件写作。当前若要做多轮科研任务，必须每轮重新上传材料，或者在宿主侧提供稳定的文件引用/会话文件上下文。这是本轮最重要的产品级缺陷。

### P1：材料审计任务触发过长工具链

E01 为“只读材料审计”，Agent 仍执行了多轮分段 shell 读取、生成 Markdown 文件和尝试上传结果文件；在没有明确要求生成文件时不应继续扩张任务。需要增加工具预算、文件读取上限和“只回答、不生成文件”的硬门控。

### P1：风格变体的事实闭合不足

E04 中 Q3 版本加入了“救援与出行安排”应用背景。即使这句话合理，也违反了该用例要求的“完全相同事实边界”。风格变换后应重新执行事实集合对齐，禁止仅为增强应用语境而补充新主张。

### P2：内部过程和 Token 成本

E03–E06 的页面 Token 较高，正式输出虽基本合格，但内部过程显示了大量 Skill 读取与路由说明。需要将“内部路由账本”与用户可见输出隔离，并为简单任务设置更严格的过程和成本预算。

## 6. 证据限制

- 本轮为真实 Web App 黑盒测试，不是可重复的 API benchmark；没有 API Key，也没有自动化接口日志。
- 浏览器内容导出接口在当前环境不可用，因此页面原始响应以本报告中的逐轮摘要和页面可见字段记录；后续正式回归应增加可保存的 Web transcript 导出。
- E03–E10 主要使用内联测试文本；只有 E01 使用三份附件并验证了首轮读取，不能把其他用例当作附件多轮检验。
- 以上评价是本轮有限样本的产品验收记录，不代表模型总体写作能力或期刊发表概率。
