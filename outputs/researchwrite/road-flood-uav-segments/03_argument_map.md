# 03 Argument Map — 论证架构

## 一句式论点
> 在城市洪涝灾后核查场景中，我们以道路片段为分析单元，把受淹像素的面积与空间分布放到道路局部坐标下组织，检验其与片段受淹情况的对应关系及适用条件，据此判断低空影像何时能直接给出片段结果、何时应转入复核。

## 主线链（background → gap → question → approach → content → validation）
1. 政策与核查任务 → 需要"定位、核查、更新"的道路级信息
2. 影像能力 → UAV 可快速获取；语义分割只能给类别 → 需要道路片段级转化
3. 缺口 → 现有输出是像素/块/网格/预设标签；未研究"受淹分布相对道路结构"的关系
4. 问题 → 上位问题（面积+分布如何反映受淹情况；遮挡如何影响；何时可判）
5. 方案 → 道路片段信息组织：可见道路范围 + 局部坐标下的面积与分布 + 遮挡记录 + 复核分流
6. 内容/创新 → 内容一（组织）→ 内容二（分布与结构）→ 内容三（遮挡与复核）；创新一（分布区分），创新二（补充/遮挡二分）
7. 验证 → FloodNet 主验证（逐步增量比较）+ RescueNet 复杂场景（强制 vs 复核）+ 一致性统计
8. 展望 → 片段结果为 Agent 化核查提供结构化输入（一段展望，不入核心）

## 论证职责分配
- 背景节：需求成立 + 影像可行性 + 问题引入（不展开方法细节）
- 现状节：文献分层（栅格制图 / 低空任务 / 道路级表达 / OBIA / 光学限制）+ 缺口收敛
- 科学问题节：研究对象定义 + 上位问题 + 子问题 + 两者关系 + 边界
- 思路节：信息组织框架（数据模型），与研究内容二去重
- 内容节：三项内容 + 对应关系 + 两项创新 + 可否定空间
- 验证节：数据选择与局限 + 样本整理 + 增量比较 + 复杂场景 + 复核反作弊 + 后续安排

## 关键设计（重写时强制执行）
- 科学问题 ↔ 研究内容 ↔ 创新点一一对应，保持原文映射（内容二→子问题一→创新一；内容三→子问题二→创新二）
- 每节只做一个职责；第四节与第五节对分布特征的列举不重复（第四节定义，第五节讲研究动作）
